名称: web-audio-play
何时使用: 用户让音箱播放网络上的音频资源——点歌、播放某角色/某节目的演唱或声音、
播放某个网页视频的声音等。这是「用浏览器在网络平台找音频 → 音箱在线播放」的通用链路。

步骤:
1. 执行仓库 bridge/ 目录下的 web-audio-play.py（路径按实际部署位置，launchd 常驻要用绝对路径），
   搜索关键词用用户点播的内容（如 "原神 沃雅妮莎"）。脚本自动按平台优先级尝试：
   - bilibili：B站（ego-browser 登录态 cookie + wbi 签名搜索 + playurl 音频流直链）
   - generic：通用浏览器捕获（打开页面抓 <video>/<audio> 与网络媒体流直链，
     不依赖任何平台 API 和登录态，小红书/抖音等任意网页都可用）
2. 用户说「不是这首/换一个」→ 先 --list 列候选让用户选序号，再 --index N 播
3. 已知 B 站 BV 号 → --bvid BVxxxx；已知视频页 URL → --url https://...
4. 用户说「停/别放了」→ 执行该脚本 --stop
注意事项:
- 脚本每次播放都现解析音频流 URL（平台流 URL 有时效/防盗链参数，绝不缓存复用）
- 播放是抢占式的：新音频直接顶掉旧音频
- 音箱 miplayer 直接在线拉流，不需要下载、不需要 ffmpeg 转码
- 防盗链兜底：脚本播前探测音频流 URL 能否裸拉，不能（403/400 防盗链平台）就
  自动起 Mac 本机流式转发（4378 端口，带 Referer/UA 转发，零落盘零转码），
  音箱改拉 http://<电脑局域网IP>:4378/stream；转发进程 30 分钟无请求自动退出
- ego lite 未运行会自动拉起；有登录态自动用登录态，无登录态也能用浏览器基础能力
- 扩展平台：在脚本 PLATFORM_ADAPTERS 注册表加适配器即可；或者直接用
  --url + generic 浏览器捕获（任意网页视频/音频页面都行）
